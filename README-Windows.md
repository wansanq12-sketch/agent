# 夜璃 Windows 版（待实机验证）

这是可运行源码包，首次安装需要网络和 Python，不是独立 EXE。推荐 Windows 10/11、Python 3.11 或 3.12 64 位。

## 启动

1. 从 https://www.python.org/downloads/windows/ 安装 Python 3.11/3.12（64 位，包含 Python Launcher）。
2. 把 Yeli-Windows.zip 全部解压到自己的文件夹，不要在压缩包里运行。
3. 双击“启动夜璃-Windows.cmd”。首次会创建独立环境并安装 Qt、图像捕获与本地 OCR 依赖，安装完成自动启动。
4. 后续双击同一个启动文件；需要更新依赖时运行“安装或更新-Windows.cmd”。启动失败查看 data/launch.log，或保留控制台错误信息。
5. 右键夜璃 → 设置，填写你自己的 API 地址、密钥和模型。原 Mac 数据与密钥不会包含在发布包中。

Qt WebEngine 提供桌面界面；聊天、记忆、技能和配置仍由本机服务保存。托盘 ☾ 可显示窗口、进入陪玩、切换置顶和退出。支持透明悬浮、拖动后落到底部、左右吸附、角色点击区域和 UI 点击区域之外的鼠标穿透。上述 Windows 原生行为仍须在实机检查，独占全屏覆盖不保证。

## 海克斯大乱斗陪玩

1. 技能管理 → 导入文件夹，选择 skills/hex-aram；也可导入单独的 hex-aram-skill.zip。导入后启用。
2. 右键 → 游戏陪玩，选择该技能，填写当前英雄和游戏版本（可留空但识别和建议可靠性会下降）。
3. 配置本地观察间隔、AI 分析最短间隔和每小时请求次数，再点“开启自动陪玩”。这会允许把匹配游戏窗口的画面发送给你配置的 AI。接口必须支持 Chat Completions 的 image_url 图片输入。
4. 启动或切回 League of Legends.exe 游戏窗口，优先使用无边框窗口模式。程序只读取前台且进程名匹配的窗口，不采集其他软件；切换软件、最小化时等待，不发送画面。
5. 本地 OCR 每 2 秒识别一次技能配置中的区域；匹配强化或商店关键词时，才进行 AI 分析。默认最短间隔 20 秒，每小时最多 60 次请求（含失败请求），相同 OCR 内容忽略数字后不重复分析。次数限制不是金额或 token 额度，仍会受图片、模型和技能长度影响。
6. 收起设置面板、输入框后，建议会在夜璃头顶展示。面板中也可查看最近建议、状态和错误。点“停止观察”即可停用；正在发送的网络请求无法撤回，返回结果会被丢弃。
7. 重启后默认停止观察；启用技能或导入技能不会自行启动监控。删掉或停用正在使用的技能会停止其观察。

游戏窗口关闭或离开前台时等待下次出现。进入新游戏进程会清空近期上下文。多个游戏共用进程或重开但进程没变时，建议手动停止并重新开启，避免上一局信息残留。识别到新的选项会更新建议，但不保证识别每次购买或选取结果。

## 技能配置

SKILL.md 保存选择策略，game-watch.json 保存匹配进程、归一化观察区域 `[左,上,右,下]` 与界面关键词。triggers 中每个列表内的词必须全部出现，外层列表满足任一组即可。支持 augment、shop、champion。可编辑技能包后删除旧技能、重新导入并启用；不要修改游戏进程。脚本仍仅保存、不执行。

这个示例包提供机制判断框架，不包含最新版本胜率榜、完整装备或强化数据库。没有匹配版本资料时，建议明确标注“按机制推理”。后续可把有来源和版本日期的策略资料放进 references 后重新导入。不能把当前实现称为经过验证的版本最优推荐。

## 已知限制与实测清单

开发环境为 macOS，Windows 窗口、OCR 依赖安装和游戏捕获尚未实机验证：

- 检查透明背景、UI 输入、右键、文件/文件夹导入、托盘退出、二次启动显示，以及拖动落地。
- 进入游戏后查看“游戏陪玩”状态。无决策界面时请求数不应增加；强化界面出现应触发一次，原画面停留不重复，刷新选项应更新。
- 确认切回浏览器、桌面或其他软件时请求数不增加；停止后即使旧请求返回也不再显示。
- 若始终等待：检查实际游戏进程名（不是启动器 LeagueClient.exe）、界面语言，以及 game-watch.json 的关键词/区域是否匹配。
- 若黑屏：切换无边框窗口再试；某些 DirectX/独占全屏画面不支持此捕获方式，需后续改接 Windows Graphics Capture。
- 若图片接口报错：确认模型确实支持图片，不能只根据模型名称判断。
- 首次本地 OCR 初始化和外部 AI 回复可能耗时，不适合要求瞬间反应的决策。OCR 误识别、界面缩放、语言和游戏版本变化都可能导致漏提醒或误触发。
- 不读取游戏内存、不注入、不自动点击或购买；只提供画面建议。

窗口捕获实现依据 Pillow ImageGrab（Windows HWND）：https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html
桌面桥接使用 Qt WebEngine / WebChannel：https://doc.qt.io/qtforpython-6/PySide6/QtWebEngineCore/QWebEnginePage.html

## 免 Python 的 EXE 构建

已增加独立 windows_main.py 入口、Yeli-Windows.spec 与 Windows 自动构建流程。使用者拿到构建成功的 Yeli.exe 后，不需要 Python；具体见 README-EXE.md。构建仍必须在 Windows 环境完成。当前源码包不包含已生成的 EXE。

## 本次交互与语音更新

- 输入框移除关闭按钮，点击外部或切换到其他应用会保存草稿并收起；发送消息后保持打开。
- 右键菜单仅保留设置、隐藏、游戏模式、退出；隐藏后可通过托盘重新显示。
- 下落从 1.5 秒缩短到 0.75 秒；动作按统一显示高度绘制，宽幅手臂不再触发整体缩小，切换图片时保留上一帧并短暂过渡。
- 运行配置不再重复提醒或声音设置；游戏模式开关位于陪玩页，右键为快捷入口。
- 聊天、设置和提醒使用浅色系。
- 新增声音页，支持语速、音量、平时朗读开关与试听。使用系统中文语音，不额外调用语音 API。Windows 需要已安装中文语音包，游戏模式回复与提醒只播报，不弹聊天气泡。关闭游戏模式恢复普通气泡。语音功能和窗口外点击需要在 Windows 实测。
